WEB3DSHARE API POSTMAN GUIDE
Base URL examples:
- Local: http://127.0.0.1:8000
- Ngrok: https://your-ngrok-domain.ngrok-free.app

In Postman, create an environment:
- base_url = http://127.0.0.1:8000
- token = empty at first

Use this URL pattern:
{{base_url}}/api/...

For protected endpoints, add this header:
Authorization: Bearer {{token}}
Accept: application/json

For normal JSON requests:
Content-Type: application/json

For upload requests:
Use Body > form-data. Do not use raw JSON for file upload.

After login or register:
1. Copy the token from data.token in the JSON response.
2. Paste it into the Postman environment variable named token.
3. Use Authorization: Bearer {{token}} for protected routes.

If you get:
- 401 Unauthorized: login again and refresh the token.
- 403 Forbidden: your user role or ownership is not allowed.
- 422 Unprocessable Content: check the validation errors in the response.
- 409 Conflict: the request conflicts with an existing state, such as duplicate active report or pending verification.

============================================================
PUBLIC ENDPOINTS
============================================================

1. MAIN API EXPLORE
Method: GET
URL: {{base_url}}/api
Headers:
- Accept: application/json
Query Params:
- Empty by default.
- Optional: search, category, tag, filter, timeframe, sort, page.
Body:
- Empty.
Postman Steps:
1. Create a new GET request.
2. Set URL to {{base_url}}/api.
3. Leave body empty.
4. Add Accept: application/json if not already set.
5. Click Send.
Expected Response:
- 200 OK.
- JSON containing models, categories, tags, and filters.
Notes:
- This is the API version of the home/explore page.

2. LIST MODELS
Method: GET
URL: {{base_url}}/api/models
Headers:
- Accept: application/json
Query Params:
- search: optional text search.
- category: optional category id.
- tag: optional tag slug.
- filter: optional, for example my_models when authenticated.
- timeframe: all_time, this_month, or this_week.
- sort: latest, top_downloads, top_views, or top_stars.
- page: optional pagination page.
Body:
- Empty.
Postman Steps:
1. Create a GET request.
2. Set URL to {{base_url}}/api/models.
3. Open Params tab if you want filtering.
4. Example params: sort=top_views and timeframe=this_month.
5. Click Send.
Expected Response:
- 200 OK.
- JSON containing paginated models, categories, tags, and active filters.
Notes:
- Use this endpoint to get model ids for detail, star, comment, report, download, edit, and delete tests.

3. SHOW MODEL DETAIL
Method: GET
URL: {{base_url}}/api/models/{model}
Headers:
- Accept: application/json
Path Params:
- {model}: model id.
Query Params:
- Optional: from=my_models.
Body:
- Empty.
Postman Steps:
1. Call GET {{base_url}}/api/models first.
2. Copy a model id.
3. Replace {model} with that id.
4. Send GET request.
Expected Response:
- 200 OK.
- JSON containing model, recommendations, categories, and is_manage_context.
Notes:
- Opening this endpoint increments model view count.

4. DOWNLOAD MODEL
Method: GET
URL: {{base_url}}/api/models/{model}/download
Headers:
- Accept: application/json
Optional Headers:
- Authorization: Bearer {{token}} if you want the API to know the current user.
Path Params:
- {model}: model id.
Body:
- Empty.
Postman Steps:
1. Get a model id from /api/models.
2. Replace {model}.
3. Send GET request.
4. Copy download_url from response if you want to open the file.
Expected Response:
- 200 OK.
- JSON containing download_url, counted, and download_count.
Notes:
- If the uploader downloads their own model while authenticated, counted is false.
- Public users can still get the download URL.

============================================================
AUTHENTICATION ENDPOINTS
============================================================

7. REGISTER
Method: POST
URL: {{base_url}}/api/register
Headers:
- Accept: application/json
- Content-Type: application/json
Body:
{
  "username": "user123",
  "email": "user@example.com",
  "password": "secret123",
  "terms_accepted": true,
  "device_name": "postman"
}
Postman Steps:
1. Create a POST request.
2. Set URL to {{base_url}}/api/register.
3. Go to Body > raw > JSON.
4. Paste the JSON body above.
5. Click Send.
6. Copy token from response field data.token.
7. Save token into Postman environment variable token.
Expected Response:
- 201 Created.
- JSON containing message and data.user, data.token, data.token_type.
Notes:
- username must contain at least one letter and one number.
- password minimum is 6 characters.
- terms_accepted must be true.

8. LOGIN
Method: POST
URL: {{base_url}}/api/login
Headers:
- Accept: application/json
- Content-Type: application/json
Body:
{
  "email": "user123",
  "password": "secret123",
  "device_name": "postman"
}
Postman Steps:
1. Create a POST request.
2. Set URL to {{base_url}}/api/login.
3. Go to Body > raw > JSON.
4. Paste the JSON body above.
5. Click Send.
6. Copy token from response field data.token.
7. Save token into Postman environment variable token.
Expected Response:
- 200 OK.
- JSON containing message and data.redirect, data.user, data.token, data.token_type.
Notes:
- The email field accepts either email or username.

9. LOGOUT
Method: POST
URL: {{base_url}}/api/logout
Headers:
- Accept: application/json
- Authorization: Bearer {{token}}
Body:
- Empty.
Postman Steps:
1. Login first.
2. Save token to environment.
3. Create POST request to {{base_url}}/api/logout.
4. Add Authorization: Bearer {{token}}.
5. Click Send.
6. Clear token from environment after success.
Expected Response:
- 200 OK.
- JSON containing message and empty data.
Notes:
- This deletes the current Sanctum token.

15. UPLOAD MODEL
Method: POST
URL: {{base_url}}/api/models
Headers:
- Accept: application/json
- Authorization: Bearer {{token}}
Body Type:
- form-data
Body Fields:
- title: Text, required.
- description: Text, optional.
- category_id: Text, required.
- tags: Text, optional comma-separated tags. Example: anime, character, game.
- model: File, required .glb file.
- thumbnail: File, required image file.
Postman Steps:
1. Login first.
2. Call GET {{base_url}}/api/upload.
3. Copy a category id.
4. Create POST request to {{base_url}}/api/models.
5. Add Authorization header.
6. Go to Body > form-data.
7. Add title as Text.
8. Add category_id as Text.
9. Add description as Text if needed.
10. Add tags as Text if needed.
11. Add model as File and choose a .glb file.
12. Add thumbnail as File and choose an image.
13. Click Send.
Expected Response:
- 201 Created.
- JSON containing message and data.model.
Notes:
- Do not use raw JSON for model upload.
- If upload fails with 422, check validation errors.

16. UPDATE MODEL
Method: PATCH
URL: {{base_url}}/api/models/{model}
Headers:
- Accept: application/json
- Authorization: Bearer {{token}}
Path Params:
- {model}: model id.
Body:
{
  "title": "Updated Model Title",
  "description": "Updated model description.",
  "category_id": 1,
  "tags": "anime, character"
}
Postman Steps:
1. Login as the model owner.
2. Get your model id from /api/models or /api?filter=my_models.
3. Replace {model}.
4. Go to Body > raw > JSON.
5. Paste and edit the JSON body.
6. Click Send.
Expected Response:
- 200 OK.
- JSON containing message and data.model.
Notes:
- Only model owner can edit.
- The actual .glb model file cannot be edited here.
- To replace the model file, delete the model and upload a new one.

Headers:
- Accept: application/json
- Authorization: Bearer {{token}}
Body:

  "note": "I want to be verified because I publish original 3D models."
}

2. Call GET {{base_url}}/api/verify.
3. Make sure eligible is true.
4. Create POST request to {{base_url}}/api/verify-request.

- Current starter rules are model count, downloads per model, account age, and rejection cooldown.
